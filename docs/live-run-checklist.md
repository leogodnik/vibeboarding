# Живой прогон: полный гайд проверки

Статическое ревью плагин прошёл. Эти вещи оно проверить не может — только реальный запуск.
Пока прогон не сделан, плагин не считается готовым к выпуску.

Нужно два прогона: «файл двойным кликом» и «настоящее приложение». Второй тяжелее и
интереснее — именно он проверяет права доступа под нагрузкой.

---

## 0. Подготовка (один раз, в обычном терминале)

```bash
# копия репозитория по пути БЕЗ пробелов — иначе установка не работает
rm -rf /tmp/vibeboarding-mkt
git clone --branch feat/vibeboarding-plugin \
  "/Users/leogodnik/Starter Skill/vibeboarding" /tmp/vibeboarding-mkt

# две чистые папки под прогоны
rm -rf /tmp/vb-test /tmp/vb-test-2
mkdir -p /tmp/vb-test /tmp/vb-test-2

# запомнить состояние глобальных настроек — сверимся с ним в конце
ls -la ~/.claude/settings.local.json 2>/dev/null || echo "глобального файла нет — хорошо"
```

## 1. Установка плагина (один раз)

В новой сессии Claude Code, запущенной в `/tmp/vb-test`:

```
/plugin marketplace add /tmp/vibeboarding-mkt
```

Путь пишется **одной строкой, без кавычек**. Если открылся диалог с полем — вставьте путь и
нажмите **Enter**, не Esc: по Esc путь уходит в чат обычным сообщением и ничего не ставится.

```
/plugin install vibeboarding@leogodnik-plugins
```

Если в ответе будет `Run /reload-plugins to activate.` — выполнить `/reload-plugins`.

Проверка, что встало (в обычном терминале):

```bash
grep -o 'leogodnik-plugins' ~/.claude/plugins/known_marketplaces.json
grep -o 'vibeboarding@leogodnik-plugins' ~/.claude/plugins/installed_plugins.json
```

Обе команды должны что-то вывести.

## 2. Режим сессии

Перед запуском переключите режим на **manual**: `Shift+Tab`, пока внизу не появится
`⏸ manual mode on`.

Это обязательно. В режиме Auto Клод обрабатывает запросы разрешений сам — и главное
наблюдение прогона окажется скрыто.

## Что наблюдать по ходу

**1. Сколько раз система спросила разрешение — и на чём именно.**
Несколько запросов в самом начале нормальны: чтобы записать файл прав, разрешение уже нужно,
сам себя скилл одобрить не может. Смотреть надо на то, что **после** появления
`.claude/settings.local.json`. Отдельно отметить, было ли что-то на `npm install`,
`node --version`, открытии файла в браузере и `git init` — эти четыре мы специально
добавляли в список разрешённых.

**2. Не смешался ли свободный текст с кнопками.**
Признак беды: вы ответили, а Клод переспрашивает то же самое или выдумывает ответ за вас.
Значит, ваш текст потерялся в ходе с виджетом выбора.

**3. Непонятные слова.**
Ищите: «репозиторий», «зависимости», «деплой», «авторизация», «фронтенд», «бэкенд», а также
английские сообщения об ошибках и коды возврата. Ничего этого быть не должно.

**4. Клод действительно запустил результат?**
Он обязан открыть результат в браузере и показать, что тот работает, — а не написать
«готово». Если написал «готово» без запуска, это провал.

**5. Есть ли в финальном отчёте готовые фразы,** что говорить Клоду дальше.

## Что проверить после каждого прогона

В обычном терминале, подставив нужную папку:

```bash
cd /tmp/vb-test          # или /tmp/vb-test-2
ls -la
find . -name '*.md' -not -path './.git/*'
```

Ожидается: файл проекта, `CLAUDE.md`, шпаргалка (`ПРОЧТИ-МЕНЯ.md`),
`.claude/settings.local.json`, `.gitignore` — и больше ничего лишнего. Ни `docs/` с ADR, ни
git-хуков, ни монорепозитория.

```bash
git log --oneline    # должен быть ровно один коммит «первая рабочая версия»
wc -l CLAUDE.md      # должно быть меньше 40 строк
```

Открыть шпаргалку и проверить главное: **имя файла и команда запуска в ней совпадают с тем,
что реально лежит в папке.** Это тот дефект, который статическое ревью поймало последним, и
проверить его можно только так.

Для прогона №2 дополнительно:

```bash
grep -A6 '"scripts"' package.json
```

Команда в `package.json`, в разделе «Как запустить» в `CLAUDE.md` и в шпаргалке должна быть
одна и та же — `npm start`. Ровно одна, не две на выбор.

## Проверка безопасности (после обоих прогонов)

```bash
ls -la ~/.claude/settings.local.json 2>/dev/null || echo "файла нет — хорошо"
```

Результат должен совпасть с тем, что было на шаге 0. Если файл появился или изменился —
это серьёзно: скилл записал права в глобальные настройки, на все проекты сразу.
